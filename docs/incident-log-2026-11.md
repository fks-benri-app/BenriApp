# 2026年11月の不具合の記録(Firestore 改革のあと)

Firestore の改革(授業ごとの投稿の保存、所属の記録、ルール)のあとに出た不具合と、原因・対応をまとめる。

## 症状と原因

1. **一部の授業しか出ない**: 授業の所属(`users/{ID}/courses`)が揃っていなかった。所属は生徒ごとの GAS の見回りでしか書かれず、古い・止まっている GAS では揃わない。
   - 対応: アプリを開いたとき、本人の権限で在籍の授業を記録する(PR #182)。
2. **base64 の授業 ID**: リンクの授業 ID は base64 で入っている。そのまま保存すると、数字の授業と別の文書になり、投稿が一覧に出ない。
   - 対応: 授業 ID を数字に直す(PR #180)。通知の設定とオフ設定も数字に揃える(PR #181)。過去の分は修復の関数で移す(PR #184、#186)。
3. **通知のオフが効かない / 設定の一覧が重複**: 設定が base64 の ID で保存されていた。
   - 対応: 読むときと保存するときに数字に直す(PR #181)。
4. **所属の二重記録**: 名簿(`courses/{ID}/members`)と生徒の所属(`users/{ID}/courses`)が、別々に書かれていた。
   - 対応: 1 回のまとめ書きで両方を書く。片方だけの生徒は、やり直しで補う(PR #183)。
5. **「もっと見る」が反応しない**: 次のページの開始位置が無いと、何もせず戻っていた。
   - 対応: 表示中の最後の時刻を開始位置にする(PR #179)。失敗の理由を画面に出す(PR #187)。
6. **permission-denied / ルールのエラー**: 投稿の一覧(collection group)の読み取りで、ルールの判定が失敗していた。30 日で約 1,700 件のエラー。
   - 対応: 投稿の `courseId` が数字のときだけ所属を確かめる(PR #188、公開済み)。効果は未確認。
   - 残る課題: 「もっと見る」の permission-denied は続いている。原因は、拒否された投稿のパスが特定できていない。
7. **公共の投稿が出ない**: 投稿が base64 の授業 ID の下に残っていた。
   - 対応: 修復の関数で、数字の授業 ID に移した(実行済み)。移したあとも、一覧に出ない(30 件より古い、または読み込みの問題)。

## 方針の決定(2026-11-26)

授業ごとに投稿を読む方法は、読み取りが上限を超えるため採用しない。生徒ごとの `users/{ID}/announcements` を読む方法(方法 A)を採用する。計算は [読み取り・書き込みの見積もり](read-write-budget.md) を見る。

## 未解決

- 方法 A への切り替え(既存の生徒文書の ID の形式の確認、過去分の移行、既読・削除の確認)。
- キャッシュが効いているかの実機確認。
